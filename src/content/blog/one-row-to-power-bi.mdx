A Power BI tile shows August revenue of 42,000. This example uses made-up
data and follows one 120-euro order in that total. The customer placed the
order in Lisbon at 00:30 on September 1.

The order passes through eight stages before Power BI reads it. Some stages
change its format or data type. The export also converts the time to UTC,
which changes the displayed calendar date from September 1 to August 31.

## Compare the same row

When two dashboards disagree, select one row that appears in both data paths
and compare it at each stage. Find the first place where the values or rules
are different.

A time zone can put the same event on a different calendar date. An amount
may be stored in cents in one table and euros in another. One report may
include only paid orders, while another includes all orders.

In this example, the checkout uses Lisbon local time and calls the order a
September purchase. The warehouse uses UTC, where the time is 23:30 on
August 31. Both timestamps describe the same purchase.

The report must state which time zone defines the month. Without that
information, a reader cannot know why a purchase made on September 1 in
Lisbon appears in the August total.
