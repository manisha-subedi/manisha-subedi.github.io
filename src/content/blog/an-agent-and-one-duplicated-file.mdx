What happens when an AI agent queries a table with duplicate data? In this
example, the August order file has been loaded twice. A revenue query returns
84,000, but the total should be 42,000.

The agent inspects the tables, runs a query, and checks the result before
answering. Scroll through the seven steps to follow the process. The data
and sequence are written for this demonstration; no AI model runs on the page.

## Checking the result

The row-count check in step four prompts the agent to investigate. An unusual
count does not prove that data is wrong, but it gives the agent a reason to
look for duplicates. The order IDs and load records then explain the increase.

Here, the agent excludes the second load from its calculation and reports
that choice with the answer. It does not change the source tables. Fixing
the underlying load still requires someone with the right permissions.

A real implementation needs checks that suit the data, such as unique order
IDs or a total reconciled with another system. It also needs a way to stop
and report a problem when those checks cannot be satisfied.
