An AI agent is a loop. It looks at something, it does something, and it
examines the result. Then it repeats. A careful analyst works the same way.
The difference is that a model has no doubt by default. The loop must supply
the doubt.

This post follows one loop from question to answer. The warehouse is small.
The fault is the most common silent fault in data work: a file that was
loaded twice. Every type test passes. Every not-null test passes. The number
is wrong by a factor of two.

## Three checks that cost one query each

The fourth step is where a careless agent stops and a careful one continues.
The checks below are cheap. Each one is a single query, and each one catches
a fault that type tests and not-null tests do not.

**Row count against history.** `SELECT month, COUNT(*) FROM orders GROUP BY
month`. A month with double or half the usual rows is wrong before anyone
reads the revenue. This catches duplicate loads and missing partitions.

**Count against distinct count.** `SELECT COUNT(*), COUNT(DISTINCT order_id)
FROM orders WHERE month = '2026-08'`. For a table with one row per order, the
two numbers must be equal. This is the direct test for duplicates.

**Sum against a known total.** The payment provider, the finance ledger, or
last month's approved report. This catches unit errors, currency errors, and
filters that drop rows in silence.

None of these checks needs a model. An agent gets value from them only if the
loop makes it run them before it answers.

## Where the fix belongs

The agent found the fault. Three fixes are possible.

1. **Add `DISTINCT` to the query.** Fast, and wrong. The next query on the
   same table has the same problem, and nobody knows.
2. **Delete the second copy of the rows.** The number is correct today. The
   next load of the same file makes it wrong again.
3. **Make the load idempotent.** Record the hash of each file. If the hash is
   already in the files table, refuse the load. The fault cannot return.

Only the third fix removes the cause. It is also the one an agent must not
apply on its own. It changes a pipeline that other people use. The correct
move is to report it, with evidence, and let a person approve it.

## What a good answer contains

The number is the smallest part. A good answer, from an agent or from an
analyst, has four parts:

- the number, 42,000;
- the query that produced it, so anyone can run it again;
- the fault it found, with the query that proves it;
- what it did not examine.

The last item matters most for agents. A model that reports only what it
examined sounds less confident. It is also the only kind you can trust with
the next question.

The steps on this page are written by hand. No model runs on this site. In a
real system the loop is the same. It is slower, it takes wrong turns, and the
fourth step is skipped more often than anyone admits.
