This is a small example with made-up warehouse data. The agent reads the
available information, runs a query, checks the result, and tries again when
the check fails.

The question is: What was the revenue in August? The warehouse has three
tables. Its August order file was loaded twice, so adding all the amounts
gives the wrong total.

The seven steps below are fixed. No model runs on this website.

## Why the check matters

The first query returns 84,000. Before answering, the agent compares the
August order count with earlier months. August has 2,480 orders, while the
earlier months had about 1,200. It then checks the order IDs and finds that
each one appears twice.

The agent excludes the second load from this calculation and runs the query
again. The result is 42,000 from 1,240 orders. It reports the duplicated file
and explains what it excluded.

The check must match the data. A row count is useful in this example. Other
systems may need a comparison with last month or a known total. An agent needs
permission before it changes source data. If it excludes rows from a result,
it should record what it excluded.

This is a small example. A real implementation would need more checks and
would have more possible failure points, but it would still need to check and
report its result.
