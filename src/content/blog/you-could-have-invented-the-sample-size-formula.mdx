An A/B test gets click rates of 50 percent for button A and 55 percent for
button B, with 200 users in each group. Is that enough evidence to choose B?

The simulation below gives a visual way to think about the uncertainty.

<BallBox />

Each ball is equally likely to be in either half of the box, so the expected
share in the shaded half is 50 percent. With 20 balls, the observed share
varies noticeably. Select "500 balls" and it stays closer to 50 percent.

The underlying probability has not changed. Counting more balls gives a
more stable estimate.

## 1. Measuring the variation

For independent observations, the standard error of a proportion is
sqrt(p(1−p)/n), where p is the underlying proportion and n is the sample
size. Using p = 0.5 gives:

- 20 balls: sqrt(0.25 / 20) = 0.11, or about 11 percentage points.
- 200 balls: sqrt(0.25 / 200) = 0.035, or about 3.5 percentage points.
- 2,000 balls: about 1.1 percentage points.

Increasing the sample size ten times reduces the standard error to about
one third, rather than one tenth.

## 2. Comparing two proportions

With 200 users per button and click rates near 50 percent, each estimate
has a standard error of about 3.5 percentage points. The difference between
two independent estimates has a larger standard error: about 5 points.

The observed advantage for B is also 5 points. A difference of that size
can arise from sampling variation even when the buttons perform equally.
This simulation counts how often one specified group leads the other by
at least 5 points:

```python
import random

def share(n, p=0.5):
    return sum(random.random() < p for _ in range(n)) / n

# 1,000 A/B tests where the two buttons are exactly the same
wins = sum(share(200) - share(200) >= 0.05 for _ in range(1000))
print(wins / 1000)    # about 0.16
```

The result is roughly one test in six. A five-point lead with these sample
sizes is not strong evidence on its own.

## 3. Estimating the sample size

Suppose we want the standard error of the difference to be about one third
of the effect we want to detect. This is a rough planning rule, rather than
a formal power calculation.

The standard error is approximately sqrt(2 · p(1−p) / n). Set it equal to
d/3, where d is the target difference, and solve for n:

n = 18 · p(1−p) / d²

For p = 0.5 and a 5 percentage-point difference, this gives
18 × 0.25 / 0.0025 = 1,800 users per button.

```python
def users_per_arm(p, d):
    return 18 * p * (1 - p) / d**2

users_per_arm(0.5, 0.05)   # 1800
users_per_arm(0.5, 0.02)   # 11250, a 2 point effect is expensive
```

A common approximation for a two-sided test with a 5 percent significance
level and 80 percent power uses a coefficient of about 16 instead of 18.
The useful part of this derivation is the relationship: detecting a smaller
difference requires substantially more observations.

## Using this in an analysis

Small groups produce less stable rates. This matters when comparing
conversion by country, defects by supplier, or performance across stores.
A group with very few observations can appear near the top or bottom of
a ranking largely because of sampling variation.

Check the sample sizes alongside the rates. For an A/B test, account for
uncertainty in both groups and choose the target effect, significance
level, and power before deciding how many users to include.
